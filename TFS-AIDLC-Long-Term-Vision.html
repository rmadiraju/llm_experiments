From Governed Enablement
to Bounded Autonomy

A direction-setting vision for how TFS accumulates software-building capability — skills, memory, judgment — in a form that survives model churn, tool churn, and team churn.

STATUS DIRECTIONAL — NOT AN IMPLEMENTATION PLAN SPINE KIRO · AGENTCORE GATEWAY · CEDAR · OKTA MARKERS PROVEN EMERGING SPECULATIVE

The question this vision answers: how does an organization accumulate software-building capability that agents can act on with earned, bounded autonomy — when every gateway, IDE, and model we use today will be replaced along the way?

01
The organizing idea

Five planes, evolving at different speeds

Today's architecture is a pipeline: IDE → rules → CLI → gateway → tools. The long-term architecture is five planes owned by different disciplines. The planes that matter most are Skill and Memory — they are where capability compounds. Gateways and IDEs are replaceable rentals; a curated skill library and a truthful memory fabric appreciate for a decade.

Design rule that follows: own the content, rent the runtime. Skills, specs, decisions, evals, and policies are ours in git. Gateways, indexes, and models are replaceable.

02
The skill plane

An economy, not a folder

Industry experts now publish skills for review, architecture, security, testing. Loading everything on every request fails three ways: context bloat, staleness, and provenance — a skill file from a blog post is a supply-chain risk when an agent will act on it. The answer is to treat skills like software dependencies: versioned, owned, signed, tested, measured.

# A certified skill in the registry skill: tfs.architecture.adr-authoring version: 2.3.1 owner: architecture-guild applies_to: [inception] triggers: semantic: "creating or revising architecture decision records" signals: ["*.adr.md", "docs/adr/**"] provenance: source: internal | vendor | community signed_by: TFS Skill Authority (Sigstore) reviewed: 2026-07-14 evals: suite: adr-quality-v4 passing_score: 0.87 telemetry: invocations_90d: 412 human_override_rate: 6%

Right skill, right time — without reading everything EMERGING

RAG is the right instinct, with one refinement: RAG the catalog, not just the content. Git remains the source of truth; the vector index is a disposable, derived artifact rebuilt on merge. Never let the index become authoritative — that inverts the trust model.

Stage 1 · Always loaded
The index card

Every certified skill contributes ~40 tokens: name, purpose, trigger hints. The agent knows what exists — the way a senior engineer knows a checklist exists without reciting it.

300 skills ≈ 12K tokens
Stage 2 · On demand
The body, retrieved

Task matches trigger — deterministic signals (file patterns, AI-DLC phase) plus semantic match — and the full body is fetched from git via hybrid retrieval: lexical + vector + graph.

~2–5K tokens per active skill
Stage 3 · After use
Unloaded

Skill bodies leave context when their task segment completes. The context window is a workbench, not a warehouse.

Net context stays flat as library grows

Skills earn their place SPECULATIVE

Every invocation logs outcome signals — acceptance, override rate, eval movement. High-override skills get flagged to owners; unused skills get deprecation notices. The library becomes a living economy where usage and quality data drive curation, not a wiki graveyard.

03
The memory plane

Making the agent a tenured engineer

A ten-year engineer is valuable for three different kinds of memory. The architecture should mirror them — and in a brownfield estate, this fabric is the asset competitors cannot download.

Semantic"Payments is event-driven because sync failed under load in 2023"Specs, ADRs, contracts — decisions with the why-notsGit — durable, reviewable, versioned

The context compiler EMERGING

The piece most of the industry is missing: agents don't need more context — they need compiled context. Before a task, a compiler assembles a task-scoped briefing inside an explicit token budget, with provenance on every chunk so claims are citable and checkable.

# Compiled context pack — budget 30K tokens task: "Add retry logic to payment webhook handler" pack: architecture-overview.md ............ 3K (project memory) payment-service spec §4 webhooks .... 5K (section, not the whole spec) ADR-019 idempotency + why-nots ...... 2K (semantic) contract: payment ↔ notification .... 1K (graph) episodic: 2026-03 retry storm ....... 2K (ranked by relevance) skills index ....................... 12K (always on) active skill bodies ................. 5K (JIT)

Memory hygiene: the gardener EMERGING

Memory that only grows becomes noise. A scheduled memory-gardener agent — running under its own persona and Cedar policy like everything else — distills episodic logs into summaries, flags contradictions between specs and observed behavior into the reconciliation loop, and proposes archival. It never deletes source records; it curates the derived layers. The tech is buildable today; the discipline is the hard part.

04
The autonomy ladder

Trust is earned per-domain, not granted globally

Autonomy is not a switch; it is a ladder where each rung is unlocked by evidence. An agent may hold L3 for test authoring in brownfield Java while holding L1 for schema migrations. The unit of trust is (agent, skill domain, blast radius) — recorded as Cedar policy, so it is enforceable and revocable, not aspirational.

L0AssistHuman writes, agent suggests
L1SupervisedHuman reviews every action
L2 · WE ARE HEREGated autonomyAPPROVE flow gates flagged actions; Cedar + approvals live
L3Policy autonomyHumans review exceptions and samples. Gate: eval scores ≥ threshold over N tasks, incident-free window
L4Fleet autonomyHumans set intent, budgets, constraints; handle escalations. Gate: L3 across domain + simulation-first + proven rollback
Scoped, never global

Autonomy level attaches to a domain and blast radius, expressed in Cedar — auditable, revocable.

Budgeted

Every autonomous run carries limits: files and services touchable, spend ceiling, wall-clock, required rollback plan. Exceeding any budget converts the run to APPROVE mid-flight.

Demotion is automatic

An incident traced to an autonomous change, or an eval drop after a model upgrade, demotes the domain one level pending review. Model upgrades are dependency upgrades: re-run evals before restoring autonomy.

Honesty about L4: fleet autonomy — agents dispatching sub-agents over A2A, humans managing by exception — is where the industry points, but nobody runs it safely at financial-services scale today. This vision's job is to make every layer we build a prerequisite for L4, not a rewrite.

05
The governance plane

The spine we have, plus three missing organs

Okta OIDC, Cedar three-state policy at AgentCore Gateway, the approval Lambda, CloudWatch audit, Kiro prompt logs to S3 — that spine extends unchanged. Three organs are missing for the long term.

1 · Evals as infrastructure — the biggest gap EMERGING

Nothing in the skill economy or the autonomy ladder works without measurement. Every certified skill ships a scenario suite, re-run on every model change. Per-persona benchmarks are drawn from our codebase — brownfield-representative, scored on correctness, standards compliance, and safety behavior (does it stop at DENY, does it request approval properly). A model upgrade that drops eval scores blocks autonomy promotion the way a failing test blocks a merge. Evals-as-code lives in git next to skills.

2 · Agent identity as a lifecycle PROVEN PATTERN

Today agents borrow the developer's Okta identity. At L3+ agents act on schedules and on other agents' behalf, so they need non-human identities: issued per agent, scoped per domain, short-lived credentials via on-behalf-of exchange, revocable independently of any human, visible in every audit record as acting_agent + on_behalf_of. NHI sprawl is a named risk — inventory with owners, reviewed quarterly, like service accounts.

3 · Simulation before production SPECULATIVE (full replay) · pragmatic versions buildable now

Before an L3+ agent executes against real systems, it executes against a shadow: ephemeral infra from IaC, synthetic-but-shaped data. The diff between simulated intent and simulated outcome attaches to the approval request — the tech lead reviews evidence, not promises. Applied by risk tier: schema changes earn simulation; a unit-test PR does not.

Observability grows up

Audit answers "what happened." Operations needs "is it healthy": SLOs for agent work (approval turnaround, override rate, eval drift, cost per merged change), sampled reasoning-trace review, and anomaly detection on tool-call patterns — an agent enumerating repos at 3 a.m. is a security signal, not a productivity one.

06
The operating model

What changes for people

Personas become a roster. Today a persona configures one agent. By L3+, the architect persona is a standing architecture agent reviewing every design for pattern compliance — personas stop being hats humans put on agents and become roles agents occupy, with humans in named oversight positions.

New roles emerge: skill curators (guild-owned), eval engineers, memory-gardener supervisors, and a platform team that runs the five planes as a product with internal customers.

The ladder shifts from "writes excellent code" toward "specifies intent precisely, verifies rigorously, and encodes judgment into skills others — human and agent — reuse." Skill-library contribution becomes a measured artifact of seniority, the way open-source contribution is today.

Brownfield stays the differentiator. The industry demos greenfield. TFS's advantage is a memory fabric that makes fifteen-year-old systems legible to agents — an asset competitors cannot download.

09
Named risks

What could make this fail

Skill supply-chain compromise
A poisoned community skill is prompt injection with a certificate. Mitigation: signing, review gate, eval quarantine for new skills.
Memory poisoning / staleness
Wrong "truth" scales worse than no truth. Mitigation: provenance on every retrieved chunk, contradiction detection, git as reviewable source.
Eval theater
Suites that don't reflect brownfield reality grant false autonomy. Mitigation: draw eval tasks from real incident and PR history.
Autonomy ratchet
Pressure to promote levels without evidence after early wins. Mitigation: promotion criteria in policy; demotion automatic; both auditable.
Human skill atrophy
Verification quality decays if seniors stop building. Mitigation: rotation through skill authorship and eval engineering as build roles.
The one-paragraph version

We are building toward an organization where skills are governed, signed packages routed to agents just-in-time; where organizational memory lives in git as truth, with graph and episodic layers that make agents behave like tenured engineers; where autonomy is earned per-domain through evals, bounded by budgets, and revoked by evidence — and where the governance spine we run today extends unchanged into a world of agent fleets. The gateways and IDEs will be replaced along the way. The skill library, the memory fabric, and the eval record are the assets that compound. And they are ours.
